# Configuration

NOTE: This file was generated by AI (GitHub Copilot) on 2025-11-14.

This document explains runtime and persistent configuration for TPNEBOT.

## Environment Variables (.env)
Required:
- `TOKEN`: Discord bot token.
- `DB_PW`: Postgres password for the postgres user (used to build async URL).
- `DEVELOPER_CHANNEL_ID`: Channel ID receiving internal error reports and stack traces.

Optional (future expansion): additional feature toggles may be added; update this file accordingly.

## Dynamic Configuration (Database Backed)
### BotConfig
- `loaded_cogs`: List of extensions to load. If empty or null, all discovered cogs load.
- `unloaded_cogs`: List of extensions to skip.
- `setup_complete`: Flag indicating initial setup done.

### ServerSettings
Per guild preferences:
- `prefix`: Custom command prefix fallback when mention not used.
- `antimp3_enabled`: Placeholder flag for anti MP3 feature.
- `watchdog_enabled`: Enables moderation audit logging.
- `auto_role_ids`: Roles automatically granted on join.
- `jail_role_id`, `mute_role_id`, `imute_role_id`, `rmute_role_id`: Role IDs for punishment states.
- booster_role_id: Donor or booster identification role.
- watchdog_channel_id, member_count_channel_id, report_channel_id, spam_channel_id, jail_channel_id: Operational channel IDs.

### CommandStatus
- `command_name`: Unique command identifier (qualified name).
- `enabled`: `True` or `False`. If `channel_id` is null applies globally.
- `channel_id`: Optional scoping of enable flag to specific channel.

### CommandRoleRestriction
Defines role gating for commands:
- `guild_id`, `command_name`, `role_id` triple unique.
Only users with at least one allowed role may execute restricted command.

### Cooldowns
Stored in CommandCooldown table with expiry timestamp. Used by invocation logic and embed generator.

### Blacklist
Global user exclusion. Contains user_id and reason.

### Wallet and Seeds
Wallet table contains server seed, previous server seed, client seed, nonce fields (names referenced in code comments). Used for fairness draws.

### Game Configuration
- `MinesSettings`: bomb_count, gem_count, multiplier define difficulty and payout model.
- `GameStats`: aggregated stats per user/game.
- `GameHistory`: per play record including hash, seeds, nonce for verification.

### Economy Entities
- `Items`, `ShopItems`: In inventory and global shop catalogs.
- `Transactions`: Movement of funds between users or system addresses.
- `BankAccoun`t: Separate bank style balance associated with wallet id.
- `Supply`: Tracks overall supply, circulating, treasury balances.
- `Block`: Ledger block containing transactions snapshot with hash chaining.

### Moderation Entities
- `Punishment`: Case records with type, reason, duration.
- `CaseNote`: Additional moderator notes.
- `JailedUser`, JailSetting: Jail system state.
- `WatchdogLog`, WatchdogSetting: Audit trail and enable flag.
- `UserAlt`: Mapping of alternate accounts.

### User Metadata
- `UserRoleHistory`: Captures role sets over time.
- `UserNameHistory`: Records name changes.
- `Reputation`: Simple reputation points.
- `ReactionSettings`: Feature toggle for self reactions.
- `LastFMusers`, LastFMvotes: Music profile and command votes.
- `UserTimezone`, UserLocation: Timezone and geolocation data.
- `FavoriteSongs`: Saved song titles.
- `BoosterRole`: Per user booster role assignment.

### Misc State
- `TempVoiceChannel`: Dynamic voice rooms lifecycle.
- `JTCSettings`: Join to create subsystem control panel.
- `Juul`: Game like shared item state.
- `Task`: Generic user tasks list.
- `Streak`: Work or activity streak count.

## Editing Configuration
Use existing commands (if implemented) or direct database updates. For new features extend `database/manager.py` with safe accessor methods.

## Migration Strategy
Currently initialization is ad hoc. For structural changes:

2. Populate backfill logic in initialization routine.
3. Consider adopting Alembic for versioned migrations when schema churn increases.
