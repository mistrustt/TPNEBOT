# Architecture

NOTE: This file was generated by AI (GitHub Copilot) on 2025-11-14.

This document explains the internal architecture of TPNEBOT.

## High Level Layers
- Core Bot (`bot.py`): Startup, logging, database initialization, dynamic cog loader, command prefix resolution, status updates.
- Cogs (`cogs/`): Modular feature units (economy, games, moderation, music, voice, ownership tools, watchdog auditing, etc.). Each cog registers commands and event listeners.
- Utilities (`utils/`): Shared logic for cooldown messaging and provable fairness.
- Data Access Layer (`database/manager.py`): Session management, async operations, configuration retrieval, initialization routines (tables, seeds setup).
- Models (`database/models.py`): ORM definitions for all persistent entities.

## Startup Sequence
1. Load environment variables via `python-dotenv`.
2. Instantiate `DiscordBot` which:
   - Sets up logging handlers.
   - Builds Postgres connection URL using `DB_PW`.
   - Loads config row asynchronously (BotConfig) to determine which cogs are enabled.
5. Sync application commands globally (`self.tree.sync()`).
6. Start background status update loop.

## Command Invocation Flow
- `invoke` override enforces:
  - Maintenance mode check (`debug_mode_active`).
  - User blacklist lookup.
  - Command and channel specific enable/disable checks (CommandStatus table).
  - Role based access control (CommandRoleRestriction).
  - Cooldown enforcement (CommandCooldown).
  - Immediate permission error handling and embed feedback.

## Error Handling Strategy
- Command errors are mapped to user friendly embeds.
- Unhandled exceptions: logged and optionally forwarded to a developer channel with stack trace segmentation to avoid size limits.
- Application command (slash) errors: respond ephemerally with standardized messages and cooldown hints.

## Logging
- Custom `LoggingFormatter` adds colored level and logger name fields to console output.
- Rotating file handler writes to `discord.log` with size based rotation.
- Structured logs include user, channel, guild context after successful command execution.

## Database Model Clusters
- Moderation: Punishment, CaseNote, WatchdogLog, JailSetting, JailedUser, ImageMuteSetting, ReportSetting, LockdownChannel, UserAlt.
- Access Control: CommandStatus, CommandRoleRestriction.
- Economy Core: Wallet, Transaction, BankAccount, Item, ShopItem, Bounty, Supply, Block (ledger), CryptoAsset, CryptoPrice.
- Game and Fairness: GameHistory, GameStats, MinesSettings, fairness seeds (in Wallet), Streak.
- User Metadata: UserRoleHistory, UserNameHistory, LastFMusers, LastFMvotes, Reputation, ReactionSettings, UserTimezone, UserLocation, BoosterRole, Blacklist, FavoriteSongs.
- Misc State: TempVoiceChannel, JTCSettings, Juul, Task.

## Fairness Subsystem
Implemented in `utils/fairness.py` using HMAC SHA256 keyed by server seed and mixing client seed plus nonce for deterministic, verifiable draws. Games consume sequential nonces: multi draw games increment nonce per draw or per shuffle swap.

## Seed Life Cycle
- Wallet possesses server seed, previous server seed (for rotation), client seed, nonce.
- Verifiers reconstruct exact outcomes off chain for auditing.
- Rotation updates server seed and archives previous for post game proofs.

## Configuration Persistence
- `BotConfig` holds loaded/unloaded cog lists and setup flags.
- `ServerSettings` stores per guild operational preferences (prefix, watchdog, roles, channels, etc.).
- `CommandStatus` toggles global and per channel command availability.

## Performance Considerations
- Async database sessions reduce blocking during high command volume.
- Cooldown checks and role restriction lookups are single row queries optimized by indices where relevant (`GameHistory` indices for audit queries).
- Rotating logging prevents disk overgrowth.

## Extensibility Guidelines
- New data types: add a SQLAlchemy model in `database/models.py`, run initialization, and create migration script if adopting migrations later.
- New command sets: create `cogs/newfeature.py` with a `setup(bot)` function, add logic, and optionally register in BotConfig loaded_cogs.
- New fairness game: implement generator in production cog and add a matching verifier function to `fairness.py`.

## Security Notes
- Private keys and seeds should not be logged.
- Developer channel only receives sanitized trace output.

## Future Enhancements (Suggested)
- Formal migration system (Alembic) instead of ad hoc initialization.
- Configurable shard support if scaling.
- Metrics endpoint (prometheus) for command usage and latency.
- Pluggable storage backends abstracted via repository layer.
